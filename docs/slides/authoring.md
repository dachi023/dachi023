# スライドの作り方

## テーマを選ぶ

テーマは2つある。どちらを使うか指定がない場合はユーザーに確認する。

| テーマ | `theme:` の値 | 用途 | 仕様 |
| --- | --- | --- | --- |
| MOSHテーマ | `mosh` | MOSH名義の登壇 | [theme-mosh.md](theme-mosh.md) |
| 個人テーマ | `personal` | 会社と関係のない個人名義の登壇 | [theme-personal.md](theme-personal.md) |

テーマを決めたら、対応する仕様のドキュメントだけを読めばよい。

## ファイルを作る

`packages/slides/src/` 直下に作る。ファイル名は発表日を先頭に付ける。

```
src/YYMMDD-<内容がわかるスラッグ>.md
```

例: `260731-dip-mosh-design-system.md`（2026年7月31日の発表）

過去のスライドには日付が付いていないファイルもあるが、新規作成時は日付を付ける。

## 共通の記法

テーマによらず共通のルール。

- スライドの区切りは `---`（水平線）を使う。
- レイアウトの指定はHTMLコメントで書く。例: `<!-- _class: lead -->`
- `lead`（表紙）は1枚目にだけ使う。
- コードブロック、テーブル、数式（`$...$` / `$$...$$`）、引用はMarkdown標準の記法が使える。
- 画像は `./assets/` からの相対パスで参照する。

## 作ったあとにやること

1. `bun run lint` でtextlintを通す。ルールの意図は [../writing.md](../writing.md) を参照する。
2. `bun run preview` で表示崩れがないか確認する。特に文字数の多いスライドは枠からはみ出しやすい。
3. `bun run build` でPDFが出力できることを確認する。
